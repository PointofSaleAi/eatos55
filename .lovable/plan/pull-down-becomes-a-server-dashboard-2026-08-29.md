# Pull-down becomes a server dashboard

Today the top-bar pull-down is a big grid of nine settings tiles with a lot of empty grey. Replace it with a working shift dashboard: settings shortcuts collapse into one slim column on the right, and everything else becomes live shift information for the server, matching the reference screens.

## Layout (tablet / web landscape)

```text
+--------------------------------------------------------------+
| KPI row: Total Sale | Total Tip | Total Hours | Ordering |    |
|          Ready to Serve | Completed            (Today vs Yst)|
+---------------------------------------------+  Settings      |
| My tickets (filter pills: All / In Progress  |  Restaurant    |
| / Unpaid / Open / Paid / Closed)             |  Menu          |
| compact ticket rows, tap to open the ticket  |  Payment       |
+---------------------------------------------+  Workforce     |
| Floor strip: floor picker + status pills +   |  Reports       |
| table chips, tap to open the table           |  Advanced      |
|                                              |  Guestbook     |
|                                              |  Support       |
|                                              |  Log out       |
+--------------------------------------------------------------+
```

- Settings becomes one single-line-per-item list pinned right, roughly 15rem wide, no descriptions, no underlines, same routes as now.
- Tablet portrait and phone: dashboard stacks (KPIs, tickets, floor), settings list moves to the end as a compact list, so nothing is lost on small screens.

## Data (existing only, nothing new)

- KPIs computed from the existing tickets in the store: sale total, tips, ordering count, ready count, completed/closed count. Total Hours comes from the existing clock-in time. The "vs yesterday" deltas use the existing ticket date range helpers; where no comparable data exists the delta is simply omitted rather than faked.
- Tickets and table chips reuse the existing ticket list and floor data, so tapping a row or a table goes to the same screens as the Tickets and Floor pages.

## AI recommendations for the server

A single compact "Suggested next" strip under the KPIs, generated by simple rules over the existing data (no backend, no AI calls): longest-waiting unpaid ticket, table sitting in Ordering the longest, checks ready to be served, and a tip-rate nudge when tips run below the shift average. Each suggestion is a tap target that jumps to the relevant ticket or table. If a real model is wanted later, this strip is the single place to swap in.

## Left navigation closed with icons

The rail already collapses; tighten it to match the reference: narrower icon column, icon-only with no labels when collapsed, active item shown as a filled rounded square, venue avatar on top and the eatOS mark plus version pinned to the bottom. Still opens by tapping the avatar or empty rail space, still defaults closed.
