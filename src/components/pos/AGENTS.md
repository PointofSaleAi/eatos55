# POS surfaces and settings screens (`src/components/pos/*`, `src/routes/settings.*`)
- ModifierOption stock is a presentation-only demo count for physical choices; ItemSheet shows remaining quantities without changing checkout, selection or live inventory, and untracked preparation instructions omit counts.
- DeviceFrame owns per-session rail placement; the NavRail grip uses pointer capture for edge drops and arrow keys for accessible placement, preserving rail expansion, routed content and phone bottom tabs.
- Cash Management uses atomic demo drawer transitions for signed-in staff, validates amounts and till state in the store, preserves cross-midnight cash, and stays separate from checkout and hardware.

- Tickets opts into non-expanding reference-style cards only in wide landscape split panes; route-driven selection and a minimum cart width preserve readable columns without changing default cards or portrait widths. The landscape detail header must not repeat what the selected card already shows (guests, order type, table, revenue centre, status), so it carries only guest, phone, arrival time, order/check numbers, server and room or note lines.

- The header settings panel uses a focused shortcut map resolved against shared settings destinations; guestbook derives read-only identities from existing POS data without fabricating contacts or combining distinct known email identities.
- Settings drawer dismissal retains the panel through its exit animation; body swipe closing is allowed only at the scroll boundary and suppresses subsequent clicks, so scrolling and gestures cannot activate shortcuts.
- Restaurant Information uses a dedicated form backed by shared demo settings, keeping structured address fields synchronized with its address summary and contact validation consistent with shared country helpers.
- Restaurant operating hours use shared demo settings with native time inputs and presentation-only 12-hour formatting, so edits persist without changing order or reporting logic.
- End of Day settings use shared demo settings and a separate start-checklist route; closing is explicitly a demo confirmation, never an implicit ticket, staff, drawer or reporting mutation.
- Schedule Information uses a dedicated editor and shared demo settings with per-day times and a reversible archive flag; row swipes reveal actions without opening the editor or archiving on dismissal, and never change employee shifts or ordering logic.
- Timed Pricing uses structured demo settings for dates, source, centre and times, separate from checkout pricing; archive/restore uses reversible swipe actions, never deletion.
- Control Center's Device Settings, Hardware Control and Guest Facing Display have dedicated routes with merged demo defaults; switches do not change hardware, payments or auth, and App Theme uses the appearance hook.
- Customer Support is the only support destination in the shared settings navigation; both the Contact Us and Help Center screens are reached from inside it and return there on back, so support never appears as separate left-nav entries.
- Workforce employee records use dedicated shared demo settings with reversible swipe archive flags and inline-editor back dismissal; saving clears list filters so the saved record is visible. PIN input is transient and never used for authentication, and hardware enrollment and payroll access are not simulated as real operations.

- Employee editors use scoped grouped-row styling with borderless inline values and a separate phone editor; shared settings controls remain unchanged to avoid restyling other destinations.
- Closing a paid ticket keeps it listed as Completed; refunds are demo-only, recorded once per ticket via refundTicket, and shown as struck-through items plus REFUNDED/REFUND payment rows (src/components/pos/ticket-refund.tsx).
- Ticket payment rows (the Paid dropdown, or closed/refunded rows) always sit directly above the totals summary on every layout — outside the scrolling item list in landscape and before the summary card in portrait — so one shared paymentsSection drives both, and expansion grows upward without moving the pinned summary.
- Left-rail icons (src/components/pos/icons/) are inline SVG components using fill/stroke currentColor — never PNG images or CSS masks — so every icon dims, hovers and highlights through the same paint path as the Lucide icons and the orderOS mark. New Order, Table Order and Tickets keep their reference artwork shapes (traced paths); only color treatment is shared, never the drawing style.
- Landscape Tickets opens with the first ticket of the current list selected: the list pane replaces the route with that ticket's detail (never openTicket, so an in-progress order draft is never overwritten), keeping the route as the single selection source; phone and portrait keep the plain list.

- New Order keeps a 24rem minimum cart width on wide layouts so guest name, mobile and arrival stay on one line; widen rather than shorten labels.
- Landscape ticket detail mirrors New Order using selected-ticket data and existing handlers, never the mutable order draft, to preserve behavior.
- Settings > Payments > Taxes is a dedicated screen (`tax-settings.tsx`) with tax rules in shared demo settings; rules never change cart or checkout totals.
- Inventory counts (Settings > Menu > Inventory) are demo-only and never affect ordering, sales or 86 status.
- Default Modifiers (Settings > Menu) are demo-only and never change New Order or product default modifiers.
- Menu Groups (Settings > Menu > Groups) are demo-only and never change New Order modifiers or add-ons.
- Settings Profile (personal info, password, two factor, PIN, photo) is demo-only; no value is ever used for authentication, SMS or real clock-in records beyond the shared session role.

- Guestbook future booking reuses floor layouts in a dedicated in-page table selector and saves guest visits only; it never starts an order or changes live table occupancy.
- Guestbook opens with the first guest selected on wide layouts (phones open on the list), so the detail pane is never empty on arrival.
- Guestbook guest list rows show initials avatars and archive (or restore) by a left swipe that reveals only the matching red icon — rows have no per-row ⋯ menu. The list toolbar is icon-only in this order: add guest `+`, archived toggle, then sort; archiving, restoring, sorting and new guests are demo-only device stores (`eatos.pos.guestbook-directory`) and never touch real contacts.
- Guestbook reservation rows carry a reversible demo no-show flag; a left swipe (touch or mouse drag) reveals only the red "No show" action (never "Undo"), while undo stays reachable from the row's tap menu so nothing is swipe-only; a no show never changes orders, table occupancy or reporting.
- Guestbook Feedback tab shows sample reviews per guest (date badge, smiley rating, expandable text with More/Less, time, text source wordmarks and reviewer); the list is deterministic per guest and demo-only.
- SwipeRow drives touch and mouse drives through pointer events, keeps the row content above the revealed action with `z-10`, and exposes `wasDragged()` (sticky until the next pointer-down, so a swipe release cannot open the row's own tap control). An action may pass `icon` to show a glyph instead of the label text; the label stays the accessible name and the strip narrows to fit.
- Archive and restore controls paint the shared `ArchiveGlyph` from `src/components/pos/archive-glyph.tsx` (a CSS-masked mark tinted by `currentColor`) — never Lucide `Archive`/`ArchiveRestore` and never a second archive drawing, so one uploaded mark covers archive and unarchive identically on every surface and appearance. In Menu settings and Taxes the mark shows alone (no "Archive"/"Restore" word, accessible name carried by `aria-label`/`title`) on row swipe strips and the archived-list toolbar toggle; the Menu settings editors (menu, category, modifier, add-on, product, default-modifier and group) carry no archive control at all, so archiving happens only from the list.
- Product tiles that carry a photo run that photo edge to edge across the card's top band (object-cover, card overflow-hidden) and drop the name to the smallest type step, so the picture keeps the visual weight; text-only tiles keep their existing name sizing. Tile content is top-aligned: name first, price (or the "Open price" tag) directly below it.
- Open-price products (MenuItem.openPrice) never quick-add silently: tile tap and + both open OpenPricePad (src/components/pos/open-price-pad.tsx), a calculator-style cents keypad that adds the item at the entered price; outside-tap closes without adding.
- The New Order panel's side lives in the `drag-grip.tsx` module store (per visit, not persisted); wide layouts flip with flex-row-reverse so the panel always stays beside the products area.
- New Order owns the options panel and inline Custom Item state; cart actions portal into the landscape rail or narrow sheet, while Custom Item replaces only the product area so cart and menu state persist.
- Add Guest replaces only the cart body in OrderPanel and saves through the shared current-order guest state, preserving products and cart actions while editing; guest addresses retain both structured U.S. fields and a formatted compatibility string so Add Guest and service-order forms stay synchronized.
- Current-order transfers use shared POS ownership state, with a resumable draft owner for unsaved orders and ticket ownership for existing checks, so ownership survives navigation and payment; clock-out ownership changes retain each ticket's transfer origin so transferred checks can be grouped and reassigned until the shift is completed.
- Typed dollar amounts use `MoneyInput` (src/components/pos/money-input.tsx) so every field fills cash-register style from the last decimal, matching the keypads.
- In a swipe-to-reveal row the opaque row background must sit on the element that translates: a static layer left above the reveal buttons hides them (the cart line's `bg-surface` once stayed put and swallowed Cancel / No Tax).
- Product-card names step font size with available width via measured steps and never break words mid-word (word-boundary wrapping); only photo tiles ellipsize.
